# PR #45: `in fn` を廃止し、値の式のローカル捕捉をやめる (実装の指示書)

## オーナーの再レビュー (PR #45 コメント 2026-09-24T04:25:39Z)

1. `graph 名前 in fn;` は採用しない。ローカル捕捉は旧実装に無かった新機能であり、`in fn` を DSL に足すくらいなら、#45 ではローカル捕捉を足さない選択肢も含めて再設計する。Rust 上の展開位置を利用者が Graphite DSL へ申告する形は避ける。
2. `#[deprecated] pub(crate) __graphite_internal_new` は不変条件ではない (同じ crate から `#[allow(deprecated)]` で呼べる)。
3. PR 本文の #41「利用者に見える変化」が旧設計のまま。

本書は指摘1を扱う。指摘2は別の実験で扱い、指摘3は親が PR 本文を直す。

## 親の設計判断

- 親は、ローカル・引数・型引数の捕捉 (オーナーの 23:39:57Z の5性質の2番目) を #45 から外す。オーナーの再レビューがこの選択肢を明示的に許しているためである。
- 親は、instance の1行目を `graph <名前>;` の1形式へ戻し、`in fn` を DSL・生成器・文書から取り除く。
- 値ありの個体・積み荷の式は、instance が最上位にあっても関数の中にあっても、宣言位置に生成する捕捉しない `fn` 項目 (af6b16c 以降の「項目位置」の経路) の本体として固定する。関数本体の中の `fn` 項目は、名前を宣言位置のブロックのスコープで解決するので、名前のすり替わりは起きない。値の式がローカルを参照すると、Rust の通常のエラー (E0434) になる。これは `fn` 項目の本体に書いた式と同じ意味である。

## 引き続き満たす性質 (回帰試験で固定する)

- 値の式の名前は instance 宣言の位置で解決し、構築の位置で同名の項目があってもすり替わらない (最上位の instance と関数の中の instance の両方)
- 値の式は `construct!` 1回につき1回だけ評価する
- 値の式を生成ファイルへ複製しない (最上位と関数の中の両方)
- `non_local_definitions` を発生させない (生成 module を最上位に置き、instance を関数の中に置く配置を含む)
- 単一の構築入口 `{instance名}::construct!(値なしの個体の値)`、`Graph` のフィールド私有、同名グラフの取り違えの拒否など、14c2e82 までの性質は壊さない
- 値の式がローカルを参照した場合にコンパイルエラーになることを compile-fail 試験で固定し、症状と対処 (値なしの個体として宣言し、`construct!` の引数で渡す) を `docs/static_graph.md` に書く
