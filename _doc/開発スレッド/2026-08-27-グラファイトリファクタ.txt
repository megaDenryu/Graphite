  #8 の実装依存順（この順で意味論を積み上げる）:

  1. #7 schema の Rust 名前空間化 — schema World を Rust module World
     に脱糖する。生成型（World::Graph、World::PersonId、World::PersonRef<'g>
     等）を全部 module 内へ閉じ込め、複数 schema 間の名前衝突を module
     で解決する
  2. #4 ID 型の規則 — node Person; なら World::PersonId（typed string
     newtype）を自動生成、node Actor(id: EntityId);
     なら既存型をそのまま使う。Node と Edge で同じ規則。「ユーザーが {Type}Id
     を手書きしている前提の命名規約依存」は廃止（破壊的変更）
  3. #1 Edge の関係構文と Edge 値型 — edge Purchase = (buyer: Person) -[info: 
     TransactionInfo]-> (product: Product);
     の役割名必須構文へ統一（旧省略形は廃止、破壊的変更）。Graph
     に属さない普通の Rust 値としての Edge 値型と、Graph 上の個体 EdgeRef
     を分離。cardinality（where each role: N..M）・unique pair・無向 edge
     の意味論もここで確定
  4. #3 NodeRef / EdgeRef と内部位置 — Ref は &Graph + 内部位置 の薄い Copy
     値。freeze 後は topology 固定・値は更新可。endpoint getter は Graph-bound
     Ref を O(1) で返し、公開 ID の hash lookup を挟まない
  5. #6 graph! の名前付き要素 — 左辺名 alice は完成後も残り graph.alice()
     静的アクセサになる。名前・公開 ID 値（@ 
     EntityId(42)）・内部位置の3概念を分離。静的アクセサは ID 検索なしの O(1)
  6. #5 traversal / 索引 / query — buyer.purchase_as_buyer() のような探索名を
     edge kind 名 + role 名から機械的に生成（自然言語の複数形推測は禁止）。role
     別索引・pair 索引で計算量契約を保証
  7. 公開 API の Rust ソース生成 — 公開 API は proc macro
     展開内に閉じ込めず、リポジトリ内の安定した場所に人間が読める Rust
     ファイルとして生成する。rust-analyzer
     の定義ジャンプで実装へ到達できることが要件
  8. #2 脱糖リファレンス最終確認 — docs/desugaring_reference.md
     を実装と一致する正本として完成させる

  現状コードとの差分（Codex への委譲時に重要な点）

  現リポジトリには既に graph_schema! / graph! / flow
