# 検収の運用

> **Development document** — 索引: `docs/README.md`

この文書は、親(委譲を出す側のClaude Codeのセッション)が実装員の成果を検収するときの運用を定める。親は、運用が変わるたびにこの文書を更新する。

検査員とは、レビュー員・構造チェック員・命名チェック員・文章チェック員という、読み取りと検証コマンドの実行だけを行い実装や修正は行わない、Claude Codeの`Agent`ツール(サブエージェントを起動する機能)の定義済みエージェントのことである。実装員とは、実装・テスト作成・git操作を行う、Agentツールの定義済みエージェントのことである。オーナーは、これらのリポジトリ横断の共通定義を`~/.claude/agents/`に置いている。Graphite固有の実装エージェントの定義(`.claude/agents/impl.md`)とは別である。

## 検査員の並行派遣

親は、実装員から完了報告を受けたら、レビュー員・構造チェック員・命名チェック員・文章チェック員の4名を1つのメッセージで並行して派遣する。4名を並行で派遣する理由は、各検査員が読み取りと検証コマンドの実行だけを行い、書き込みを行わないため、互いの作業環境を競合させないことにある。

レビュー員が故意破壊(検査対象の一部を一時的に改変して挙動の違いを確かめる検証手法)を行う場合、親は、作業ツリーを変更せず`git archive`で作った一時コピーの上で故意破壊を行うようレビュー員へ指示する。

## 自己申告の扱い

親は、実装員の完了報告に含まれる「検査済み」「確認済み」という語を自己申告として扱い、検収の証拠にしない。親が検収の証拠にするのは、親自身が派遣した検査員の結果と、親自身が実行した検証コマンドの結果だけである。

過去に2件の事故があった。1件目は、実装員が、実装員自身には届いていない検査員の結果を受領済みと報告した事故である。2件目は、実装員が、粗いgrepで生成コードのdocコメントの欠落件数を0件と誤報したが、実際には627件の欠落があった事故である。

## IDEの診断を判断材料にしない

親は、IDEの診断(vscode-lsp-mcpの`get_diagnostics`の呼び出し結果と、Claude Codeが会話へ自動で差し込む診断の通知の両方)を検収の判断材料にしない。IDEの診断は、実装員や故意破壊の作業が途中の状態のファイルを拾い、実際には存在しないエラーを表示することがあるためである。親は、`cargo build`と`cargo test`の実測結果だけで判断する。

## 命名チェック員への裁定

親は、命名チェック員を派遣するとき、次の2件の裁定を派遣のプロンプトへ毎回明記する。この2件はオーナーが承認済みの裁定である。

1. 命名チェック員は、値を返すメソッドの名詞形の名前(`名前()`・`entity()`のような、概念名をそのまま返す名前)を合格と判定する。Rustのgetterの慣例に合わせるためである。
2. 命名チェック員は、「〜できる」「〜である」「〜になる」の形で終わるBDD形式のテスト関数名を合格と判定する。

親がこの2件を書かないと、命名チェック員は同じ指摘を毎回再検出する。

## 検証の落とし穴

`examples/`配下の各クレートはルートのCargo workspaceのメンバーではないため、`cargo test --workspace`は`examples/`配下の試験を1件も実行しない。親は、`examples/`配下に触れた変更を検証するとき、各exampleのディレクトリへ移動して個別に`cargo test`を実行する。

## GitHubへの記録

親は、issueに進捗があるたび、何をしたかとなぜそうしたかをissueのコメントに書く。

親は、issue・PRの本文とコメントに書くリポジトリ内のファイルパスを、`https://github.com/megaDenryu/Graphite/blob/main/<path>`のリンク形式で書く。

親は、issue・PRへ投稿する前に、その文章を文章チェック員に検査させる。
